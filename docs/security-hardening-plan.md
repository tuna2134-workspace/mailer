# Security hardening plan

This plan records the repository audit performed before hardening changes. A row is not complete until its named regression and, where applicable, PostgreSQL or interoperability test passes. External DNSSEC, MTA-STS fetch/cache, malware scanning, and public-MTA interoperability remain external or manual until a real adapter/test exists.

## Existing controls confirmed

- Workspace lints forbid unsafe code and deny `unwrap`/`expect`; protocol inputs use bounded parsers.
- SMTP command/reply lines, DATA lines, message size, recipient count, MIME nesting/parts/decoded bytes, and IMAP literals have explicit limits and regression/fuzz coverage, though the gaps above remain.
- PostgreSQL is authoritative. SMTP local acceptance calls the repository commit before emitting success; queue leasing is short-transaction `SKIP LOCKED` with a random lease token.
- Null MX and implicit MX behavior are separated. The policy core refuses to treat non-`Secure` DNSSEC state as DANE validation.
- Documentation already states that SMTP remote delivery is not exactly once and that MTA-STS retrieval, DNSSEC validation, TLSA matching, and TLS-RPT aggregation are external.

## Implemented in this hardening tranche

- Outbound TLS now uses a closed transport-policy type. Opportunistic failure reconnects on a fresh plaintext SMTP connection; REQUIRETLS, MTA-STS, DANE, and administrator-strict modes never take that fallback. Production MTA-STS retrieval and DANE validation remain external, so they are not advertised as verified.
- Loss of the final DATA reply is persisted as `ambiguous` and retried with the documented duplicate-delivery risk. Queue leases remain token-guarded and recoverable after expiry.
- ARC sealing requires PostgreSQL metadata proving that Authentication-Results was locally generated; submitted fields cannot activate ARC trust.
- SMTP and IMAP share a bounded process-local authentication limiter across reconnects and protocols, with IP/account/pair pressure, progressive delay, configurable exact versus IPv6 /64 aggregation, and generic failures. Existing unknown-user dummy password work remains in place.
- DATA and BDAT reads enforce a configurable rolling minimum-throughput budget in addition to absolute time and size bounds.
- IMAP now rejects connections above its global admission limit immediately instead of retaining accepted sockets while waiting for a semaphore permit. Per-source admission/rate budgets remain open work.
- Hickory was upgraded to 0.26.1 for the 2026 CPU/unbounded-loop advisories, the unmaintained PEM parser was removed, and CI now runs RustSec plus cargo-deny license/source/ban policy.

## Execution order

1. Outbound transport policy type, opportunistic reconnect fallback, strict failure, and TLS downgrade tests.
2. Explicit post-DATA ambiguity from SMTP client through durable queue outcome.
3. Authentication-Results/ARC trust boundary.
4. Shared auth and connection/rate/progress limiting.
5. PostgreSQL crash/commit and queue lease integration tests.
6. IMAP audit, fuzz/corpus expansion, observability, graceful shutdown, dependency policy, and deployment hardening.
